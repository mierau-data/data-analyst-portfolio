# Разработка A/B-тестирования и анализ результатов

> **Учебный проект** курса «Аналитик данных» Яндекс Практикум, 2026. Кейс продуктового аналитика развлекательного приложения с «бесконечной» лентой коротких видео.

## Задача

Приложение зарабатывает на ежемесячной подписке (лента без рекламы) и на показе рекламы неоплатившим пользователям. Команда рекомендательных систем разработала новый алгоритм, который, по их гипотезе, показывает более интересный контент.

Как аналитику, мне нужно рассчитать параметры A/B-теста для проверки этой гипотезы, оценить корректность его проведения и проанализировать результаты.

## Данные

Три таблицы с сессиями пользователей (различаются только периодом наблюдения):

- `sessions_project_history.csv` — исторические данные, 2025-08-11 — 2025-09-23 (для EDA и baseline);
- `sessions_project_test_part.csv` — первый день теста, 2025-10-14 (мониторинг);
- `sessions_project_test.csv` — весь период теста, 2025-10-14 — 2025-11-02.

Основные поля: `user_id`, `session_id`, `session_date`, `session_start_ts`, `install_date`, `session_number`, `registration_flag`, `page_counter`, `region`, `device`, `test_group`.

## Стек

Python, Pandas, Matplotlib, Seaborn, statsmodels, Jupyter Notebook.

## Что сделано

**1. Работа с историческими данными (EDA):**
- анализ динамики числа активных пользователей и доли регистраций;
- анализ распределения числа просмотренных страниц в первых сессиях;
- выбор порога «успешной» сессии (≥ 4 страниц) и проверка стабильности baseline (~30%).

**2. Подготовка к тесту:**
- расчёт размера выборки методом `NormalIndPower.solve_power` при α = 0.05, мощности 0.8, MDE = 3%, baseline p = 0.3 — **41 040 пользователей на группу**;
- расчёт длительности теста с учётом двух групп — ~9 дней при трафике ~9 900 пользователей в сутки.

**3. Мониторинг A/B-теста:**
- проверка равенства числа пользователей в группах A и B;
- проверка отсутствия пересечений пользователей между группами;
- проверка равномерности распределения по устройствам и регионам (по уникальным пользователям).

**4. Проверка результатов:**
- формулировка гипотез, выбор целевой, прокси- и барьерных метрик;
- сравнение доли успешных первых сессий в группах;
- оценка статистической значимости через двусторонний z-тест на пропорции.

## Гипотезы

- **H₀:** новый алгоритм не влияет на долю успешных первых сессий: `p_A = p_B`;
- **H₁:** новый алгоритм увеличивает долю успешных первых сессий: `p_B > p_A`.

## Ключевые выводы

Тест проведён корректно: группы сопоставимы по размеру, пересечений между ними нет, распределения по устройствам и регионам равномерны.

Доля успешных первых сессий составила 31.57% в группе A (старый алгоритм) и 31.47% в группе B (новый алгоритм). Разница −0.11 п.п. статистически незначима: двусторонний z-тест дал **p-value = 0.8433** (>> α = 0.05), нулевая гипотеза не отвергается.

Новый алгоритм рекомендаций не улучшил ключевую метрику вовлечённости. **Внедрять нововведение в текущем виде не рекомендуется** — стоит доработать алгоритм и провести повторный эксперимент.
